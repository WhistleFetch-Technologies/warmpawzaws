# Same URL, different APK behavior — vendor gallery parity guide

## What this means

Both APKs open **`https://vendor.warmpawz.com`**. If **our APK uploads** and **your APK does not**, the bug is **not** “old prod JS” on the URL (both see the same JS). The difference is what is **baked into each APK’s native shell**.

Android WebView + Capacitor need native pieces that are **not** downloaded from the URL:

| Baked into APK | Effect if missing/wrong on your build |
|----------------|----------------------------------------|
| `assets/capacitor.config.json` with **`CapacitorHttp.enabled: true`** | Large JSON/base64 upload fails in WebView XHR |
| **`cap sync`** pulling `@capacitor/camera` + File Picker into Gradle | 0-byte files, picker broken on Android 11+ |
| **`<queries>`** in merged `AndroidManifest.xml` | Gallery/camera intents don’t resolve |
| **`node_modules`** at `apps/vendor-web` (Capacitor **8.x**) | Old Capacitor 5/6 project ignores `CapacitorHttp` config |

Copilot often rebuilds **`android/` only** from the keystore repo. Our working build always runs from **`apps/vendor-web`** with `npm install` → `npx cap sync android` → `gradlew`.

## Fix instructions (your system must match this exactly)

### Step 0 — Use the full Capacitor project root, not android alone

Working tree:

```
apps/vendor-web/                    ← RUN ALL COMMANDS FROM HERE FIRST
  package.json                      ← @capacitor/core ^8.3.1, camera, file-picker
  capacitor.config.json
  node_modules/                     ← REQUIRED after npm install
  android/
    app/src/main/assets/capacitor.config.json   ← GENERATED by cap sync
    capacitor.settings.gradle                   ← GENERATED — lists camera modules
    app/capacitor.build.gradle                  ← GENERATED
```

**Wrong:** open only `keystore/apps/vendor-web/android` with no parent `package.json` / `node_modules`.

---

### Step 1 — Parent `capacitor.config.json` (source of truth)

File: `apps/vendor-web/capacitor.config.json`

Must match:

```json
{
  "appId": "com.warmpawz.vendor",
  "appName": "Warmpawz Vendor",
  "webDir": "dist",
  "server": {
    "url": "https://vendor.warmpawz.com",
    "androidScheme": "https"
  },
  "android": {
    "allowMixedContent": false
  },
  "plugins": {
    "CapacitorHttp": {
      "enabled": true
    }
  }
}
```

---

### Step 2 — Install JS deps and sync native (non-negotiable)

```powershell
Set-Location apps\vendor-web
npm install
npm run build:prod
npx cap sync android
```

**Stop if `cap sync` errors.** Do not run `gradlew` until sync succeeds.

---

### Step 3 — Verify generated files BEFORE `gradlew` (parity gates)

Run these checks on **your machine**. If any fail, your APK will not match the working one.

#### Gate A — Baked config inside APK inputs

```powershell
Get-Content apps\vendor-web\android\app\src\main\assets\capacitor.config.json
```

**Required output must include:**

```json
"CapacitorHttp": {
  "enabled": true
}
```

If this file is **missing** or **`CapacitorHttp` is absent/false** → you did not `cap sync` from `apps/vendor-web`, or you edited the wrong `capacitor.config.json`.

#### Gate B — Camera + picker native modules linked

```powershell
Get-Content apps\vendor-web\android\capacitor.settings.gradle
```

**Must include lines like:**

```
include ':capacitor-camera'
include ':capawesome-capacitor-file-picker'
```

If only `:capacitor-android` appears → `package.json` missing camera plugins or sync not run from vendor-web root.

#### Gate C — `capacitor.build.gradle` dependencies

```powershell
Get-Content apps\vendor-web\android\app\capacitor.build.gradle
```

**Must include:**

```
implementation project(':capacitor-camera')
implementation project(':capawesome-capacitor-file-picker')
```

#### Gate D — Manifest queries (permissions unchanged)

File: `apps/vendor-web/android/app/src/main/AndroidManifest.xml`

**Add only** `<queries>` before `<application>` — do **not** remove or add `<uses-permission>` lines:

```xml
<queries>
    <intent>
        <action android:name="android.media.action.IMAGE_CAPTURE" />
    </intent>
    <intent>
        <action android:name="android.media.action.VIDEO_CAPTURE" />
    </intent>
    <intent>
        <action android:name="android.intent.action.GET_CONTENT" />
    </intent>
    <intent>
        <action android:name="android.intent.action.PICK" />
    </intent>
</queries>
```

After edit, run **`npx cap sync android` again** (manifest is not overwritten by sync, but sync must still be current).

#### Gate E — Capacitor major version

```powershell
npm ls @capacitor/core @capacitor/android @capacitor/camera
```

Expect **8.x** (e.g. 8.3.1). If you see **5.x or 6.x**, `CapacitorHttp` in config may not behave like the working APK — upgrade to match `warmpawzaws` `package.json` and re-run `cap sync`.

```powershell
.\gradlew.bat assembleDebug
```

1. **Uninstall** `com.warmpawz.vendor` from the test phone.
2. Install `app\build\outputs\apk\debug\app-debug.apk`.

### Step 5 — Runtime proof (same URL, prove native layer)

On the phone with **your** new APK:

1. USB debugging on → desktop Chrome → `chrome://inspect` → Warmpawz Vendor WebView.
2. Gallery → pick one center photo.
3. Console **must** show:

   `[GALLERY] Uploading via JSON base64`

4. In console, run:

   ```javascript
   (async () => {
     const { Capacitor } = await import('https://vendor.warmpawz.com/_next/static/chunks/...'); // OR from app context:
     return typeof Capacitor?.Plugins?.CapacitorHttp !== 'undefined' || 
            (await import('@capacitor/core')).Capacitor.isNativePlatform();
   })();
   ```

   Simpler check in inspect console (while on vendor app):

   ```javascript
   window.Capacitor?.isNativePlatform?.()
   ```

   Should be `true`. If upload still uses XHR only, look for log:

   `[postJsonWithXhr] CapacitorHttp failed, falling back to XHR`

   → **Gate A failed** (HTTP plugin not enabled in baked config).

## Compare your APK vs working APK (binary diff)

If you have **warmpawzaws-built** `app-debug.apk` (works) and **your** `app-debug.apk` (fails):

1. Rename both to `.zip`, extract.
2. Diff these paths:

| Path inside APK | What to compare |
|-----------------|-----------------|
| `assets/capacitor.config.json` | `CapacitorHttp.enabled` must be `true` on both; if yours is false/missing → sync issue |
| `AndroidManifest.xml` (merged) | `<queries>` for IMAGE_CAPTURE, GET_CONTENT, PICK |
| `classes.dex` / size | Large version skew → different Capacitor generation |

PowerShell quick extract check on **your** APK before installing:

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem
$zip = [System.IO.Compression.ZipFile]::OpenRead("C:\path\to\your-app-debug.apk")
$entry = $zip.Entries | Where-Object { $_.FullName -eq "assets/capacitor.config.json" }
# Or unzip to folder and type the file
```

## Typical “same URL” mistakes on the other system

| Mistake | Symptom |
|---------|---------|
| Edited root `capacitor.config.json` but never `cap sync` | APK assets lack `CapacitorHttp` |
| Keystore `android/` only, Capacitor 5 project | Config key ignored; no native HTTP |
| No `npm install` in `vendor-web` | `cap sync` links wrong/missing modules |
| Missing `@capacitor/camera` in package.json | 0-byte image after pick |
| No `<queries>` in manifest | Picker doesn’t open or intent fails |
| Installed new APK without uninstall | Testing old WebView/cache (uncommon for upload path) |
| Release build with `minifyEnabled true` stripping plugins | Debug works, release fails (our build uses `minifyEnabled false`) |

---

## If parity gates pass but upload still fails

Then compare **runtime** on both APKs on the **same device**:

- Console: exact error after `[GALLERY] Uploading via JSON base64`
- Network tab in inspect: POST URL, status, body size
- Auth headers (vendor token) — same account on both APKs

That is no longer an APK-shell parity issue.
